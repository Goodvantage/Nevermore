# Implementation decisions · 7 November 2026

- macOS 26 (Tahoe) and Swift 6. Independent AppKit implementation, no chat/composer WebView. The baseline moved from macOS 15 to 26 so the shell can use Liquid Glass, split-view inspectors and glass controls without availability checks or fallback appearances.
- Bundle/callback identity: `ch.goodvantage.Nevermore` / `ch.goodvantage.Nevermore://oauth`. Nevermore is a Goodvantage app, developed on forge.goodvantage.cloud, which establishes the identity's ownership for public distribution. It replaced the development identity `ch.lkmc.Nevermore` before any release. Changing it requires updating the plist and dedicated server registrations together.
- The rename from `app.nevermore.mac` landed after the first real-account validation. The owner registered both callbacks in a space-separated list; fresh sign-in and Keychain-backed restart recovery now pass under the new identity too. Preserve the tested legacy build and its existing sandbox/Keychain data. No automatic cross-container or credential migration is claimed. The same holds for the move from `ch.lkmc.Nevermore`: a Frappe site needs the new callback registered (both callbacks space-separated during the transition), and accounts are added again under the new identity.
- One shared account session per local site/user identity; per-account GRDB stores and Keychain secrets. Cookies and HTTP response caching are disabled in authenticated transport.
- Continuous native NSTextView transcript with a working set bounded by 500 messages and 4 MiB of source input. This makes cross-message selection native and avoids one native text view per persisted message. Older history is paged; this is a bounded cache, not a complete offline archive. Tables and arbitrary HTML cannot execute web content.
- Server-owned reminders/scheduled text; no local awake timer pretending to guarantee delivery. Existing FCM enrollment is deliberately not used for APNs.
- Channel archive and mute controls use source-verified document updates, with server permissions authoritative; archived channels remain in the authorized account directory and are hidden or shown per window. Hiding an archived channel is not treated as permission revocation. Broader batch actions still require verified contracts. Browser handoff is available.
- Mac Share extension is deferred by its lifecycle/security gate. Ordinary Finder/paste attachments work independently.
- No automatic update feed is enabled without the owner's update signing key and hosting configuration. Release packaging and notarization require real credentials. No unsigned feed or credentials are supplied as a shortcut.
- Live deployment validation is distinct from mock contract tests. The owner's dedicated public client now passes browser sign-in/consent, basic authenticated reads, a live connection and restart recovery on one Raven 3.1/Frappe 16 site. The full server/authentication/permission/media matrix remains open. Production provider credentials were not supplied.

- Organization working hours and per-user after-hours messaging are distinct from this Mac's incoming-notification quiet hours. The latter are explicitly local and account scoped; no nonexistent server start/end preference is written.
- Rich-text metadata retains generated list markers separately from typed characters. Unsupported constructs remain read only, with browser editing available; local synthetic fixtures do not establish a complete web/mobile interoperability corpus.
- Native checks use a disposable demo store so repeated runs do not depend on an earlier demo draft. Development builds retain ordinary demo drafts separately.
- Long code collapses in the transcript and opens in a native reader with horizontal scrolling and optional wrapping. Reading text contains no editor round-trip metadata; hidden spoilers are removed before rendering or copying. Code routes are opaque, account-bound and invalidated by edits, deletion and known permission loss.
- Spoiler authoring uses an independent inline mark so mentions and custom emoji retain their semantic identities. Formatting expands selections to whole graphemes and semantic entities; code blocks remain protected from unsupported inline marks.
- Rectangular tables up to 50 rows and 20 columns use native TextKit table blocks, including validated spans. Unsupported geometry keeps its complete text fallback. Native tables remain read only; plain copying supplies tab-separated cells and RTF preserves the table. Hidden cell spoilers stay masked.
- Custom emoji catalog pages use the permission-filtered Frappe list API and validated same-origin image paths. The native picker searches names/keywords, retains stable IDs and cancels on account/context changes. Shortcodes provide safe readable fallback without automatic image downloads. Reaction toggles run once and require refresh after an uncertain result.
- Reacting starts with a one-click row of eight Unicode emoji; the full picker is its More Emoji… button. The row lists the account's most-used reactions from Raven's `most_used_reactions` (shared across the user's devices), then Raven web's default quick emoji. It holds Unicode emoji only, because custom emoji would need automatic image downloads. A server without the endpoint, or a failed read, keeps the defaults and retries after ten minutes, without an alert. The row never reorders while open, follows its message across scrolling and re-renders, and marks the user's existing reactions, which a click removes. Hover actions use the arrow cursor and a hover highlight, because the transcript's I-beam hid that they are buttons. Choosing a reaction is the commitment: it is sent even if the user switches conversations or closes the window right after the click, which cancel only an open row or picker. Each message takes one toggle at a time. A refresh that another toggle overtook is asked for again, so the reactions shown are never older than the last accepted toggle. Alerts about a toggle's result appear only while its conversation is still shown, since it reloads from the server when shown again.
- The composer's emoji button opens the system Emoji & Symbols popover pointing at the button. The palette takes no anchor: it points at the rect the first responder reports for the start of its selection, so `ComposerView` answers that one query with the button after a click and with the text at every other time. The answer is single-use and expires after five seconds, because the palette asks again before it inserts, and input methods ask the same question. While text is being composed the question may be the input method's, so it gets the insertion point and uses up the answer. If another view keeps the keyboard focus, the button opens nothing, since the palette would type into that view. ⌃⌘Space and the Edit menu keep the insertion-point anchor. The wait before the popover appears is the palette's own: its process quits about a minute after its last use, and on macOS 27.0.1 the popover came up about 135 ms after the click while that process was running and about 350 ms when it had to launch. Launching the process ahead of the click, when the pointer reaches the button, saved about 110 ms; it was left out because it depends on undocumented behaviour of a system process for a small gain.
- File promises are copied synchronously during the provider callback into private immutable snapshots, using descriptor-relative paths that refuse symlinks. The provider destination is shared as required by AppKit. Cancellation and limits bound accepted data; an external provider cannot be forcibly stopped, so late writes receive best-effort cleanup and real provider behavior remains a manual gate.
- Shared drafts track input revisions, pending imports, local acceptance and failed-save recovery across windows. Quit waits for local persistence, not network delivery. Closing the initiating window does not abandon an already requested send or retain its acceptance lock.
- Packaging supplies explicit macOS 26 compiler triples for each architecture, then merges slices. A linker minimum-version field alone does not establish source availability checking with the current Swift Build defaults.
- Workspace search intersects accessible non-DM channel IDs through `channel_id`. Raven overwrites client `parent_channel_id` filters with its account-wide permission filter, so workspace scope is explicitly labeled channel messages; account search includes thread replies. Results are narrowed again on first load and refresh. Saved searches are local, account-scoped settings and are purged with account removal. Cached saved/mention results require explicit membership metadata and can under-report.
- Queued sends check canonical channel/thread-ancestor archive state before uploading and before transmission. Known archived targets pause without a request; their immutable operations remain available for explicit review/retry. The server's send endpoint does not enforce archive state, so this is client behavior; an external archive change between the final read and send still requires a server-side precondition to eliminate completely.
- Dock attention defaults to a dot for the server attention inbox or unread DMs, with all-unread and no-badge alternatives. Numeric unread badges use server logical-send counts; they are never reconstructed from file/message rows. Notification preferences and channel access are rechecked after network reads and before enqueuing a notification.
- The window shell follows Mail and Messages: an `NSSplitViewController` with a glass sidebar (conversations only, with type symbols, unread weight and counts), a full-height conversation pane, and a Tahoe inspector item for threads. Inbox, Threads, Later and Outbox stay auxiliary windows (one per collection, reused), reached from the toolbar, the Go menu (⌘1–⌘6) and any window via app-level forwarding.
- Per-window history (Go ▸ Back and Forward, ⌘[ and ⌘]) restores the conversation, message anchor, scroll offset and search text, which the sidebar cannot. It is still a secondary path in a chat window, where the sidebar and chooser do the switching, so Back/Forward is an optional toolbar item in Customize Toolbar rather than a default one in front of the conversation title. Its chevrons are separate toolbar items, so each one validates its own direction.
- The composer floats as Liquid Glass over the transcript, which scrolls beneath the toolbar and the composer. Read receipts and the "following" edge use only the readable band between them, so a message hidden under glass is never acknowledged.
- A transcript keeps its bottom edge when its pane changes shape. AppKit holds the top of a scrolled text view: a shorter pane cuts off the newest messages, and a new width keeps the first visible line. A chat is read from the bottom, so `TranscriptViewportKeeper` remembers the line at the bottom of the readable band on every scroll and puts it back after a window resize, a sidebar or inspector change, full screen, or a composer that grows, and once more when a live resize ends, where AppKit scrolls its own first line back; a transcript that follows its newest message stays on it. The anchor is a character, not a message, so it also holds inside a message taller than the window. Restoring is not a scroll by the reader and leaves the remembered line alone, so narrowing a window and widening it again ends where it began. The thread inspector uses the same keeper.
- Between a decision to show something else (another conversation, Jump to Latest) and the render that shows it, the pane still holds the previous text. Its scroll position says nothing about the reader then, so it changes neither the "following" state nor the read position, loads no earlier messages, and no message in it is acknowledged or offers hover actions. If that render fails, rows of the same conversation are observed again and rows of another stay ignored.
- A sent message belongs at the newest end of the conversation. Sending from a page of history, or from the context of a message opened from search or the inbox, leaves that view for the newest messages and follows them, as Jump to Latest does. Before, the queued message was drawn below the older messages in view and left the pane once it was delivered. A requested message is placed by the first render that has it, which is at once when the message is cached: in view when it was opened from search or the inbox, at its remembered offset when Go ▸ Back restored it. The server's answer adds what the cache lacked, and scrolls to the message only while it is still the one requested.
- Message commands act on the message at the caret, which is tinted; hover actions and a type-aware contextual menu expose the same commands. Typing while the transcript has focus starts a message; Tab leaves the composer, Option-Tab inserts a tab.
- Prompts and confirmations raised by a window are sheets on that window. Errors stay app-modal because they often arrive after their window closed or changed account. Sending outside working hours keeps an app-modal choice so no other window can change the shared draft meanwhile.
- Edit ▸ Undo in the composer uses the conversation's shared draft undo manager rather than the window's, so undo works from the menu and keyboard and stays coherent across windows showing one draft. Swapping between a draft and an edit restores a valid, collapsed insertion point; an empty draft starts with plain typing attributes rather than inheriting the edited message's style.
- ⌘F finds within the loaded transcript (Mail's Find); ⌥⌘F focuses the toolbar's server search; ⌘R replies (Mail), and collection windows keep ⌘R for Refresh because Reply is unavailable there.
- Window tabs are supported (File ▸ New Tab, the tab bar's + button) and tab groups are restored after relaunch; saved states from earlier builds restore as standalone windows.

## Themes

- Themes are plain data in `NevermoreCore` (`ThemeCatalog`): palettes, fonts, wallpaper motifs and ornaments. The app draws them; the core audits them. Classic has no palette and keeps every system color, font and the opaque text background exactly as before, so choosing it is a true return to the native look.
- Every palette must pass `ThemeAudit` in the unit tests: body text, names, links, timestamps and alerts at 4.5:1 against the gradient, body text and code text (on its code wash) still at 4.5:1 over the worst wallpaper pixel (each motif and ornament color composited at its opacity, alone and stacked where they can overlap: ornaments sharing an anchor, or filling the pane), and other text at 3:1 there. Tertiary text uses the audited secondary color rather than a translucent one, and text in the accent's place (your own reaction counts) uses the link color, since the accent is audited only for shapes. Avatars and reply bars take each author's name color. A new theme or color change that fails does not build green.
- The wallpaper is static layer content (a gradient, ornaments redrawn only on resize, and a repeating motif tile from a deterministic layout), so scrolling never redraws it. Celebrations are a four-second Core Animation burst that removes itself.
- Theme fonts and colors apply to reading text only. The composer keeps the system font: its HTML encoder reads a fixed-pitch font as inline code, so a monospaced theme would otherwise turn every sent message into code.
- The catalog's themes are presets, and the user's changes to one are a `ThemeCustomization`: a sparse set of overrides stored per preset (JSON text under `themeCustomizations`), never a copy of the theme. A field the user left alone keeps following the preset when a later version improves it, an edit dragged back to the preset's value stops counting as an edit, and Reset to Preset is an empty customization. Customizations are kept per preset rather than as one shared "custom theme", so browsing other presets never discards them. Stored values are untrusted: decoding skips the fields it cannot read (a mistyped color), the motif and ornament entries it cannot read (a shape a later version removed) and the presets whose entry is no customization, each without costing its neighbors, and `sanitized` clamps or drops what the renderer cannot honor (list sizes, opacities, tone). An empty motif or ornament list is the user's choice of no art; a list that lost every entry it had falls back to the preset. Classic has no palette and cannot be customized.
- The contrast audit gates the shipped presets, not the user's edits. A customized theme may be hard to read; the editor runs the same audit on what is drawn and names the roles that miss their minimum instead of refusing the edit.
- Backdrop opacity is one preference for every theme, not a theme setting, so it survives a theme switch. It is applied in the model (`Theme.fadingBackdrop(to:)`): gradient stops blend toward the plain text background of the theme's tone and the wallpaper, ornament and sidebar tint opacities scale with it. The result is an ordinary theme, so the windows, the gallery previews and the audit all see exactly what is drawn, and no view needs a second alpha path. The window itself stays opaque.
- Theme edits apply to the chrome at once and re-render transcripts only after a 150 ms pause: fonts and name glows are baked into the attributed transcript, and a dragged slider would otherwise re-read each conversation from its store many times a second. The pause is timed in the common run loop modes, so resting in mid-drag refreshes too, and a backdrop opacity change, which leaves the text alone, does not cancel a re-render an edit is waiting for. Renderer caches are keyed by what they draw (motifs, density and seed for wallpaper tiles; one poster slot per preset that remembers its theme), so edits neither show stale art nor grow a cache.
- A theme is app-wide (`NSApp.appearance`), stored as its raw identifier in user defaults; unknown values fall back to Classic. Increase Contrast hides the wallpaper and Reduce Motion skips celebrations regardless of the user's switches. Native self-checks start from Classic, check the presets without the user's customizations and backdrop opacity, and restore the user's theme preferences afterwards.

## Composer typing

- Markdown shortcuts follow Raven's web editor (Tiptap's input rules), so the same keys work in both clients: `> `, `- `/`* `/`+ `, `1. `, three backticks, `**bold**`/`__bold__`, `*italic*`/`_italic_`, backtick code, `~~strike~~` and `||spoiler||`. Matching is pure text logic in `NevermoreCore` (`MarkdownShortcut`). Bold, italic, strikethrough and spoiler delimiters need a word boundary before the opening one and no space inside, so `snake_case_names` and `2 * 3 * 4` stay literal. A backtick pair needs no boundary, exactly as in Tiptap's code rule (the opening backtick only must not follow another backtick). Nothing converts inside code. Headings and rules are left out: the composer has no command for them either.
- A shortcut is formatted one run-loop step after the key that completed it, in an undo group of its own. `UndoManager` groups everything registered during one event, so formatting inside the key's event would make one Undo remove the typed character as well, and typing it again would convert again. Now the first Undo restores exactly what was typed and typing on stays literal. Every other editing command first applies a waiting shortcut, so none of them sees half-converted text. Undo/Redo checkpoints restore typing attributes as well as the caret, so text typed after Redo stays outside the shortcut's formatting.
- Quotes and lists keep their marker text (`│ `, `• `, `1. `) in the editor, as before. A line break inside one now adds the next marker, and an empty line, or Backspace at the start of a line, takes that line out of the block. Before this, a new line in a quote or list was sent as part of it but shown without a marker, and there was no way to leave the block.
- These rules edit only the paragraphs they concern and re-render only lists (to renumber them). Re-rendering the whole draft would be simpler, but the renderer drops empty paragraphs, so the first shortcut would delete the user's blank lines. Each rewrite is built in full, checked with the same encoder and grammar as sending, and applied as one text replacement; when the check fails the keys keep AppKit's plain behavior. Nested lists and lists inside quotes, which only arrive from other clients, keep that plain behavior too.
- A line break carries quote, list or code metadata only while the next paragraph belongs to the same block, because AppKit takes the typing attributes of an empty last line from the line break before it. Text without paragraph metadata ends an open quote in the encoder. Before, a typed line under a quoted line was shown outside the quote and sent inside it.
- Blocks inserted next to existing text (shortcuts, Format ▸ Bulleted List/Numbered List/Block Quote) get quote, item and code names of their own. The renderer numbers them from 1 in every render, and the encoder joins neighbours by name: a line made a list item under an existing list was shown as a second bullet and sent as a paragraph inside the first item. A new quote still joins the quoted line directly above or below it.
- Send looks at the encoded text, not the editor's string, to decide whether a draft is empty: an empty quote or list item is all marker and was sent as an empty message. A draft the codec cannot read back reports an error instead of silently refusing it or sending unchecked content; whitespace-only drafts can exceed the codec's limits too.
- A marker is text the app generated, so no command deletes part of one. With the caret in front of or inside a marker, typing and a line break act behind it, and Backspace or Forward Delete take the line out of its quote or list. A selection that reaches into a marker or across lines is deleted by one rule for typing, pasting, cutting and deleting: the line the selection starts in keeps its marker (deleting everything leaves one empty quoted line, as deleting a whole list leaves one bullet in Notes), markers further inside go with their lines, and what is left of the last line joins the first line's block. Without it, typing over a selected quote showed plain text and sent a quote. Text moved by drag and drop or inserted by a service does not pass through this rule yet.
- Send, Schedule and saving an edit format a waiting shortcut before they read the draft. The formatting is deferred by one run-loop step (see above), so a Return processed in that gap would otherwise send the typed marker and convert the composer afterwards.

## Composer links and previews

- A web address typed or pasted into the composer becomes a link, and every address still plain is linked when the message is sent, scheduled or saved after an edit. Raven's web editor does the same (autolink while typing, `linkifyOnSend` before sending) for a reason that applies to every client: the server reads a message's links from its `<a>` elements only, and the web client does not linkify text when it renders. An address sent as plain text is not clickable for anyone and never gets a preview. Only `http` and `https` addresses with a scheme are linked; bare domains are left alone because "e.g" and file names look like them. Sentence punctuation directly after an address stays outside the link, including the fullwidth marks of Chinese and Japanese text.
- Linking a typed address waits for the space or line break after it and is a step of its own, like a Markdown shortcut, so Undo removes the link and keeps the typing. Inside code nothing is linked.
- A link whose text is its own address follows that text: after `https://a.example` is linked, typing `/b` at its end gives one link to `https://a.example/b`, and deleting back to `https://` removes the link. Without this, editing the visible address would leave the link pointing at the old one. These links carry a marker attribute (`Nevermore.AutoLink`) that the encoder ignores; a link restored from a draft gets the marker when an edit first touches it and its text still equals its address. A link behind a label (Format ▸ Insert Link, or an address pasted over selected words) keeps its address when the label changes, and Insert Link on an automatically linked address makes it such a link. The correction rewrites link attributes directly after each change instead of registering undo steps: the attributes are derived from the text, and Undo and Redo change the text and run the same correction.
- The preview card above the composer shows what the first link in the draft leads to: title, description, a thumbnail, the site's name and always the host of the address as written, so a page cannot pass for another site through its own `og:site_name`. Everything from the page is shown as plain text. The card belongs to the person writing and is not part of the message; Raven builds its own previews for readers after the message is sent. The draft card has no dismiss control because Raven does not offer per-message preview suppression. The card is 440 points wide where there is room. That width is a layout preference weaker than the split view's hold on its panes, so the card narrows with the conversation and never widens it: at a higher priority it kept the conversation wider than a window at its smallest size, hidden or not.
- The app fetches the page itself. Raven's `preview_links.get_previews` only returns previews the server has already stored for sent messages; it never fetches a new address, so there is nothing to ask the server for while a message is still a draft. Apple's LinkPresentation was not used because it gives no control over which hosts, redirects and sizes are fetched.
- The fetch treats the address as hostile input, since a link can be pasted from anywhere (`LinkPreviewPolicy`, `LinkPreviewLoader`):
  - HTTPS only, default port only, no credentials in the address, DNS names only (no IP literals, no `localhost`, `.local`, `.internal` and similar names). An `http` address is linked but gets no card.
  - The host is resolved first and every address it resolves to must be public; the unspecified, loopback, private, link-local, carrier-grade NAT, benchmarking, documentation, multicast and reserved IPv4 ranges are refused (also for an IPv4 answer carried in an IPv6 address), for IPv6 everything outside `2000::/3` and its tunnel and documentation blocks. Redirects are not followed by the transport; the loader checks each hop the same way and gives up after five.
  - The connection uses only those checked addresses, not a second DNS lookup. A small C bridge to macOS's system libcurl pins its DNS entry and checks the numeric endpoint again before opening a socket. The original URL still supplies the TLS server name, certificate/hostname validation and HTTP Host header. Libcurl supplies TLS and HTTP framing; no third-party package is added. Synchronous DNS resolution and curl work run on a utility dispatch queue, never Swift's cooperative executor. Proxies and connection reuse are disabled so neither can bypass the endpoint check; networks that require a proxy get no card.
  - No cookies, no credentials or netrc, no response cache, no HTTP authentication and no client certificate. TLS uses the system trust policy. The User-Agent carries the crawler names sites expect from link previewers and does not name the app, so a site learns its visitor's network address, as from a browser, and nothing about the chat client.
  - Only `text/html` and XHTML answers are read, at most 2 MB (the same cap as Raven's server-side fetcher; large sites reach their title only after several hundred kilobytes of inline script) and the transfer stops at `</head>`. Pictures must be PNG, JPEG, GIF, WebP, AVIF or HEIC of at most 2 MB (no SVG) and are decoded as a small ImageIO thumbnail, and only when the file declares a pixel size within limits. Eight seconds of silence or twenty seconds in total end a request.
- A page is fetched once the address is complete (linked), not while it is being typed, and again only after the typing pauses when a linked address is edited. Opening a conversation whose saved draft holds a link, or editing a message that holds one, fetches that page too: the card describes the text in the composer, however it got there. Results are cached in memory for the session, failures (of pages and of pictures) for five minutes. The card does not retry a failed fetch by itself; it asks again once the address has changed or left the composer. Settings ▸ General ▸ "Preview links while you write" turns the fetching off; addresses are still linked.
- Demo sessions and the self-checks use fixture loaders and never reach the network.

## Conversation motion and reactions

- An unread, unmuted conversation shows a raven beside its count; the count stays the information and the accessibility label is unchanged. The raven's eye is lit for a direct message or for a `raven_mention` event seen while the app runs. Raven's unread counts carry no per-conversation mention flag, so mentions from before launch are not marked. Design and run notes are in `docs/design/`.
- Space in the transcript reads on: Quick Look when the selected message has a file, otherwise a page down, otherwise the next conversation with a raven. It never selects a muted conversation; Next Unread Conversation still does.
- Reactions can be dragged or thrown from the quick row and always end in the one `react` toggle a click sends; position and tilt are not stored. Clicking a chip toggles the reader's own reaction, as on Raven web. Adding a Unicode reaction registers Undo on the conversation's undo manager, which the transcript shares with the composer. A sticker with no accepted toggle after eight seconds falls off and nothing is retried.
